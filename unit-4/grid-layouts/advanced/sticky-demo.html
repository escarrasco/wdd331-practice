CSS Grid

CSS Grid gives you two-dimensional control over layout. You can define explicit columns and rows, place items precisely, or let auto-placement fill gaps intelligently.

Named grid areas make templates readable. Instead of counting column numbers, you sketch the layout with ASCII-art strings and assign semantic names to zones. The browser does the math.

Grid is best when the layout drives the content — when you have a known structure and need items to conform to it. Combine it with subgrid to share tracks with child elements and achieve perfect cross-card alignment.

The minmax() function lets tracks grow and shrink between a minimum and maximum size, while auto-fit and auto-fill let the browser decide how many columns fit at any given viewport width.

Implicit tracks — rows or columns the browser creates automatically when content overflows the explicit grid — can be sized with grid-auto-rows and grid-auto-columns.

Flexbox

Flexbox excels at one-dimensional layout: distributing items along a single axis with flexible sizing. It is the right tool when content determines how much space each item needs.

The main axis runs in the direction of flex-direction. Items grow and shrink along it according to flex-grow, flex-shrink, and flex-basis. The shorthand flex lets you set all three at once.

Alignment on the cross axis uses align-items and align-self. Spacing along the main axis uses justify-content. Both axes together let you center content in a container in two lines of CSS.

Flex wrapping — enabled with flex-wrap: wrap — lets items flow into new rows or columns when the container is too narrow, producing a rough responsive grid without any media queries.

For nav bars, button groups, form rows, and card footers, flex remains the most direct tool: reach for it when content quantity or length is unknown and items should simply line up and distribute naturally.

Logical Properties

Logical properties replace physical directions — top, right, bottom, left — with writing-mode-relative equivalents: block-start, inline-end, block-end, inline-start.

In a left-to-right horizontal writing mode, block is vertical and inline is horizontal, so margin-block-end equals margin-bottom and padding-inline-start equals padding-left.

Switching to a vertical writing mode or a right-to-left language flips the mapping automatically. Layouts built with logical properties need no override stylesheets for international contexts.

Shorthand logical properties — margin-block, margin-inline, padding-block, padding-inline — accept one or two values just like their physical counterparts.

Browser support is now excellent. The practical advice: start new projects with logical properties and convert physical ones as you touch existing code. Mixing the two in the same rule is the only thing to avoid.

Custom Properties

CSS custom properties — also called CSS variables — store reusable values that cascade and inherit just like any other CSS property. Declare them with a double-dash prefix and consume them with var().

The most powerful use of custom properties is as design tokens: named values for colors, spacing, typography, and shadow that every other rule references. Changing a token in one place updates the whole system.

Custom properties can be reassigned in any selector scope, including media queries and :is() selectors. This makes them ideal for theme switching: flip a handful of token values on :root or [data-theme] and the entire page repaints.

The @property rule lets you register a custom property with a type, initial value, and inheritance flag. Registered properties can be animated with @keyframes, something unregistered properties cannot do.

Combine custom properties with calc(), clamp(), and color-mix() to build expressive systems where relationships between values are encoded in the CSS itself rather than hard-coded everywhere.
